# StyleBook Partner App — Project Instructions

> The salon app for owners, managers and specialists: today's bookings, requests, calendar, staff, services, gallery, shop orders, stock, earnings and AI marketing.
> Platforms: **web/tablet first, Android and iOS** (phone works with a Today-first layout). Bundle id `com.stylebook.partner` · web `partner.stylebook.lk`.
> Requirements: StyleBook SRS (`PTN-*`, `BR-*`, `AI-*`, `ENG-*`). Backend contract: `openapi.json` from the API project. UI reference: prototype boards "Partner app (salon, web/tablet)" and "Partner app (mobile)", and `STYLEBOOK_FLUTTER_STYLE_GUIDE.md` ("Amber & Ink", the same design system as the Client app).

---

## 1. Tech stack

| Concern | Choice |
|---|---|
| SDK | Flutter 3.x stable, Dart 3 (pinned with FVM) |
| Repo | Monorepo with Melos: `apps/partner`, shared `packages/sb_core`, `sb_api`, `sb_ui` |
| State | Riverpod 2 (`riverpod_generator`, `AsyncNotifier`) |
| Routing | go_router with typed routes, path URL strategy on web, deep links for push; adaptive shell: side menu on web/tablet (≥ 900 px), floating bottom nav + More on phone |
| API | Dio + interceptors (auth refresh, idempotency key); client generated from OpenAPI |
| Models | `freezed` + `json_serializable` |
| Real-time | `web_socket_channel`: new requests, status changes, chat, orders, leave requests |
| Storage | `flutter_secure_storage` (tokens), `drift` (offline cache of today and the calendar), `shared_preferences` |
| Auth | Mobile OTP or email + password; roles from token claims |
| Roles | Owner, Manager, Specialist: menu and actions filtered by role claims (the API still checks every call) |
| Calendar | `syncfusion_flutter_calendar` (resource day/week, drag to move) or a custom grid |
| Charts | `fl_chart` (earnings) |
| Tables / export | `data_table_2`; CSV export generated by the API |
| Media | `cached_network_image`, `image_picker`, `file_picker` (web), pre-signed S3 upload |
| Push | `firebase_messaging`, `flutter_local_notifications` (new request, leave request, low stock, dispute) |
| i18n | ARB files: English first, Sinhala and Tamil |
| Design system | `sb_ui` package: `SbTheme.light()` + `context.sb` tokens and shared widgets (shared with the Client app) |
| Fonts | Manrope 300–800 via `google_fonts`, bundled for release |
| Quality | `very_good_analysis`, `flutter_test`, `mocktail`, golden tests, `integration_test` |
| Monitoring | `sentry_flutter`, Firebase Analytics |
| CI/CD | GitHub Actions + Fastlane; web on Firebase Hosting |

├── shell/              # adaptive shell: sidebar (web/tablet), floating black nav + More (phone), role guard

## 5. Rules for building

- **Git & Branching Preconditions**: Before starting any new development or task, verify `git status`. If uncommitted changes are present, ask the user to commit and push them before proceeding. Always create and switch to a dedicated feature branch (e.g. `feature/<name>`) from `main` before authoring code.
- **Design**: follow `STYLEBOOK_FLUTTER_STYLE_GUIDE.md`. Actions are black pills (white pills on dark surfaces); orange is for accents only (links, focus, active menu text, highlighted stat); use `sb_ui` components and `context.sb` tokens, never hard-coded colours, sizes or shadows. The Partner and Client apps share the same theme.
- Web/tablet uses the cream sidebar with a white lifted active item; phone uses the floating black nav with labels (Today, Calendar, Staff, Gallery, More).
- Today is the home screen on every device. Requests needing action always sit at the top with a count.
- Every destructive action (decline, no-show, delete photo, stock down) asks for confirmation; decline and stock changes need a reason. Destructive confirm buttons are red (`danger`).
- Status labels and colours are the same as the client app (`BR-01`): Requested, Confirmed, Checked in, In service, Completed, Declined, No-show.
- Specialists only see their own calendar and earnings unless given manager rights.
- Phone layout hides heavy screens (inventory, AI Studio, earnings detail) behind "opens on web" links.
- The API is the source of truth for free slots, prices, fees and payouts; the app never computes them on its own.
- Money is formatted from cents: `LKR 1,500`. Dates as "Thu 29 Oct, 9:30 AM".
- Accessibility: 44 px touch targets, labels on icon buttons (FAB, close, ± steppers), text scales to 200 %.
